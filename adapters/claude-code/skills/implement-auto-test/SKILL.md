Этап конвейера conveyor: реализация автотестов.
**Агент:** qa-autotest-engineer. **Предусловие:** есть autotest-plan.md
(`meta.json → stages['autotest-plan'].done`). implement-plan НЕ ждём: тесты
пишутся параллельно с разработкой.

**Корень плагина.** `${CLAUDE_PLUGIN_ROOT}` — Claude Code подставил сюда
абсолютный путь при загрузке скилла. Ниже и во всех файлах этапа он обозначен
плейсхолдером `<CONVEYOR_ROOT>`: подставляй этот путь БУКВАЛЬНО в каждую
команду и каждый путь. Переменной окружения с таким именем нет — `$` с
фигурными скобками раскроется в пустоту, а окружение между вызовами Bash не
сохраняется. Остался незаменённый текст вместо пути — возьми каталог из строки
«Base directory for this skill» выше и поднимись на два уровня.

Прочитай и выполни точно: `<CONVEYOR_ROOT>/core/stages/_common.md` и
`<CONVEYOR_ROOT>/core/stages/implement-auto-test.md`.

Кратко:
1. resolve-config; задача из meta.json. Установи рабочую область:
   `scope.mjs set --stage implement-auto-test --type <FE|BE> --task
   <TASK-ID>` (запись — только репо автотестов; `clear` при завершении).
   Проверь чистоту working tree репозитория автотестов.
2. Обнови копию автотестов (`update --mode write`); создай ветку
   `<TASK-ID>-autotests` (`git-ops branch`), запиши autotestBranch.
3. Запусти qa-autotest-engineer: вход — ТОЛЬКО autotest-plan.md,
   specification.md и путь к рабочей копии автотестов (кодовая база FE/BE
   не открывается, дифф реализации не готовится); реализация автотестов
   из таблицы «Автотесты» плана («Класс» — куда, «Реализация» — что именно)
   по соглашениям репозитория автотестов, с отметкой колонки «Статус» каждой
   выполненной строки в autotest-plan.md
   (`[ ]` → `[x]`; остальной текст плана не правится). Затем агент собирает
   тестовый код БЕЗ ЗАПУСКА ТЕСТОВ (компиляция тестов командой из соглашений
   репозитория) и чинит ошибки сборки. Тесты на этом этапе не запускаются и
   отчёт не пишется: проверки пишутся по спецификации, под старое поведение
   продукта тест не подгоняется. Агент возвращает итог сборки и расхождения
   с планом — запиши их в `meta.json → stages['implement-auto-test']`:
   `build: { status: ok|failed|blocked, command, note }` и
   `deviations: { "<ID теста>": "<причина>" }` (нет расхождений — `{}`).
4. Цикл ревью (core/stages/_review-loop.md, домен autotests): агент reviewer
   находит замечания (тесты он не запускает — проверяет код и сборку),
   qa-autotest-engineer спорит и исправляет (2 раунда по
   умолчанию; нерешённые blocker/major → эскалация). Итог — в meta.json
   (`review`); в отчёт его перенесёт `/conveyor:run-auto-test`.
5. Сверка плана с кодом:
   `tms-cases.mjs coverage --task <задача> --repo <копия автотестов> --base <mainBranch>`
   — у каждой строки таблицы «Автотесты» плана «Статус» `[x]` и ID найден в
   коде; `untouched` — план велел создать или изменить тест, а ветка его не
   тронула; `extra` — тесты сверх плана (`placeholder: true` — кейса в
   Zephyr у него не будет: скажи пользователю). `ok:false` с `unexplained` →
   один возврат агенту (дописать / отметить / назвать причину), причины — в
   `deviations`, повтор; остаток — пользователю. `ok:false` с `problems`
   (сверка не выполнена, например нет общей точки с основной веткой) — не
   агенту: устрани причину и повтори. Ключи из `staleDeviations` убери из
   `deviations`; при повторном запуске этапа `deviations` собирается заново. Сверка до коммита не
   случайна: потерянный тест — это ещё и недостающий тег, то есть лишний
   прогон джобы.
6. Скилл коммитит финальные изменения в ветку и спрашивает про push: пушу я /
   пушите сами (дождись подтверждения) / не пушить. MR — по отдельному
   подтверждению.
7. `validate-task-folder`; meta.json: stages.implement-auto-test.done рядом с
   build, deviations и review. `scope.mjs clear`. Сводка: по плану /
   реализовано, расхождения, итог сборки тестового кода. Следующий шаг —
   `/conveyor:update-tms` (кейсы в Zephyr, ключи вместо заглушек в
   @TmsLink), затем `/conveyor:run-auto-test` (когда implement-plan завершён
   и функционал на стенде) — он прогонит тесты и напишет report-auto-test.md.
