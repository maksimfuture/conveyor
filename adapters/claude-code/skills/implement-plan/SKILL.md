Этап конвейера conveyor: реализация.
**Агент:** frontend-developer или backend-developer (по типу задачи).
**Предусловие:** есть plan.md.

**Корень плагина.** `${CLAUDE_PLUGIN_ROOT}` — Claude Code подставил сюда
абсолютный путь при загрузке скилла. Ниже и во всех файлах этапа он обозначен
плейсхолдером `<CONVEYOR_ROOT>`: подставляй этот путь БУКВАЛЬНО в каждую
команду и каждый путь. Переменной окружения с таким именем нет — `$` с
фигурными скобками раскроется в пустоту, а окружение между вызовами Bash не
сохраняется. Остался незаменённый текст вместо пути — возьми каталог из строки
«Base directory for this skill» выше и поднимись на два уровня.

Прочитай и выполни точно: `<CONVEYOR_ROOT>/core/stages/_common.md` и
`<CONVEYOR_ROOT>/core/stages/implement-plan.md`.

Кратко:
1. resolve-config; тип из meta.json → агент. Возьми список репозиториев из
   плана: `plan-repos.mjs --file <папка задачи>/plan.md --workspace <root>
   --type <FE|BE>`;
   `ok:false` → стоп (план не говорит, где править — назад на /create-plan).
   Установи область ПО ЭТОМУ СПИСКУ: `scope.mjs set --stage implement-plan
   --type <FE|BE> --task <TASK-ID> --write <repos>` (`clear` при
   завершении/остановке). Проверь чистоту working tree в КАЖДОМ
   (`git-ops clean-check`), грязная хотя бы одна → стоп до правок.
2. В КАЖДОМ репозитории: `update --mode write`, ветка `<TASK-ID>-<slug>`
   (`git-ops branch`) — имя одно на все. Запиши `implementBranches`
   (юнит → ветка + baseSha). Повторный запуск — продолжай существующие ветки.
3. Запусти агента: реализация строго по plan.md (тег `Репозиторий:` у шага
   говорит, куда писать), отметки чекбоксов, прогон тестов/линтеров в каждом
   репозитории, отклонения — в plan.md. Понадобился репозиторий вне плана →
   агент возвращает запрос на уточнение; спроси пользователя, допиши план,
   перевыстави область.
4. Цикл ревью (core/stages/_review-loop.md, домен frontend/backend): ОДНО
   ревью на объединённом диффе с разметкой `### Репозиторий <id>` — reviewer
   находит замечания (включая рассогласование между репозиториями),
   разработчик спорит и исправляет (2 раунда по умолчанию; нерешённые
   blocker/major → эскалация).
5. Скилл коммитит финальные изменения в ветку задачи в каждом репозитории
   (push/MR — по подтверждению + permission-prompt guard-хука, в порядке
   мержа из плана). Обнови meta.json (stages.implement-plan.done + review +
   implementBranches). Напечатай итог таблицей «репозиторий → ветка →
   коммиты». Следующий шаг — `/conveyor:create-autotest-plan`.
