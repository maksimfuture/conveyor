description: Прогоняет автотесты задачи в Jenkins на стенде и пишет отчёт о прогоне report-auto-test.md (статусы тестов задачи, сборка, ревью, расхождения с планом). Запускать после /conveyor:implement-auto-test, когда разработка (implement-plan) завершена и функционал развёрнут на стенде; можно перезапускать (перезапуск упавшей сборки). Спрашивает, на стенде ли функционал, проверяет, что ветка автотестов запушена, подбирает MCP-инструменты Jenkins, запускает джобу по тегам изменённых тестов (теги можно изменить), опрашивает статус раз в 3 минуты. Аргумент TASK-ID. Запускать только по явной команде пользователя.

Этап конвейера conveyor: прогон автотестов в CI и отчёт о прогоне.
**Агент:** не требуется — всё делает скилл. **Предусловие:** завершены
implement-auto-test и implement-plan (`meta.json → stages`), есть
autotest-plan.md и autotestBranch.

**Корень плагина.** `${CLAUDE_PLUGIN_ROOT}` — Claude Code подставил сюда
абсолютный путь при загрузке скилла. Ниже и во всех файлах этапа он обозначен
плейсхолдером `<CONVEYOR_ROOT>`: подставляй этот путь БУКВАЛЬНО в каждую
команду и каждый путь. Переменной окружения с таким именем нет — `$` с
фигурными скобками раскроется в пустоту, а окружение между вызовами Bash не
сохраняется. Остался незаменённый текст вместо пути — возьми каталог из строки
«Base directory for this skill» выше и поднимись на два уровня.

Прочитай и выполни точно: `<CONVEYOR_ROOT>/core/stages/_common.md` и
`<CONVEYOR_ROOT>/core/stages/run-auto-test.md`.

Кратко:
1. resolve-config; задача из meta.json; проверь предусловие (implement-auto-test
   и implement-plan завершены, есть autotest-plan.md и autotestBranch) —
   не выполнено → остановка без рабочей области. `tms-cases.mjs pending
   --task <папка задачи> --repo <копия>`: непустой `pending` (заглушки задачи в
   плане или коде) —
   предупреди и спроси: сначала /conveyor:update-tms или прогнать так.
2. `scope.mjs set --stage run-auto-test --type <FE|BE> --task <TASK-ID>` —
   запись в репозитории запрещена, только артефакты; `git-ops locate` для
   автотестов. При завершении/остановке — `scope.mjs clear`.
3. Спроси (AskUserQuestion): «Функционал задачи уже на стенде?» — «нет» →
   джобу не запускаем, причина «функционал ещё не на стенде».
4. Проверки: ссылка на джобу `links.autoTest.pipelineUrl`
   (`repos.autoTest.linkPipelineAutoTest`); ветка запушена —
   `git-ops pushed --path <копия> --branch <autotestBranch>`: `pushed:false`
   с `checkFailed:false` → причина «ветка не запушена» (сам не пушишь);
   с `checkFailed:true` → проверка не удалась (сеть/origin), push НЕ
   советуй, причина — «не удалось проверить ветку в origin»; MCP-инструменты Jenkins
   подбери сам среди доступных в сессии по трём ролям (запуск сборки, статус,
   результаты тестов); несколько кандидатов — спроси; инструмента запуска нет —
   джобу не запускаем (curl вместо MCP не годится). Спроси разрешение на
   запуск, назвав джобу, ветку и инструмент.
5. Теги из изменённых веткой тестов (`@Tag("...")`) — покажи список и спроси,
   запускать по ним или по другим (список редактируется). Запусти сборку с
   выбранными тегами в `TAGS`, опрашивай статус раз в 3 минуты до завершения
   (дольше часа — спроси, ждать ли дальше).
6. Напиши report-auto-test.md по каркасу
   `<CONVEYOR_ROOT>/core/templates/report-auto-test.md` — целиком, сам, без
   агента и только по фактам: строки — по таблице «Автотесты» плана (тот же
   ID, «Файл теста» — колонка «Класс», «Название» — из «Тест-кейсов»);
   «Статус» — по результатам сборки (пройден / упал / пропущен; не нашёл
   тест в результатах, нет инструмента результатов или джобу не запускали —
   «нет данных»; строка плана `[ ]` и теста нет в результатах — «не
   реализован»); «Расхождение с
   планом» — из `stages['implement-auto-test'].deviations`, «Ревью» — из
   `stages['implement-auto-test'].review` meta.json; «Прогон в CI» — джоба,
   ветка, теги, сборка, статус, числа сборки. Джобу не запускали → отчёт всё
   равно пишется: «джоба с автотестами не запускалась: <причина>», ссылка на
   джобу и ветка на месте. Повторный запуск переписывает отчёт целиком —
   как и отчёт прежней схемы (написан implement-auto-test до прогона): из
   него до перезаписи перенеси «Расхождение с планом», если в meta.json нет
   `deviations`.
   Затем `validate-artifact --file <задача>/report-auto-test.md --type
   report-auto-test --plan <задача>/autotest-plan.md` — `ok: true`,
   `planMismatch.missing` пуст, `placeholders` пуст.
7. `validate-task-folder`; meta.json: `stages['run-auto-test'].done = true`,
   `autoTestJob: { url, status }` рядом с autotestBranch (не запускали —
   `{ url: null, status: "не запускалась: <причина>" }`). Конвейер задачи
   завершён.
