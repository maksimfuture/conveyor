Этап конвейера conveyor: тест-кейсы в TMS (Zephyr Scale).
**Агент:** не требуется — всё делает скилл. **Предусловие:** завершён
implement-auto-test (`meta.json → stages`), есть specification.md,
autotest-plan.md, report-auto-test.md и autotestBranch.

**Корень плагина.** `${CLAUDE_PLUGIN_ROOT}` — Claude Code подставил сюда
абсолютный путь при загрузке скилла. Ниже и во всех файлах этапа он обозначен
плейсхолдером `<CONVEYOR_ROOT>`: подставляй этот путь БУКВАЛЬНО в каждую
команду и каждый путь. Переменной окружения с таким именем нет — `$` с
фигурными скобками раскроется в пустоту, а окружение между вызовами Bash не
сохраняется. Остался незаменённый текст вместо пути — возьми каталог из строки
«Base directory for this skill» выше и поднимись на два уровня.

Прочитай и выполни точно: `<CONVEYOR_ROOT>/core/stages/_common.md` и
`<CONVEYOR_ROOT>/core/stages/update-tms.md`.

Кратко:
1. resolve-config; задача из meta.json; проверь предусловие (implement-auto-test
   завершён, есть specification.md, autotest-plan.md, report-auto-test.md и
   autotestBranch) и
   ссылку на тест-кейсы проекта `repos.autoTest.linkTMS` — не выполнено →
   остановка без рабочей области.
2. `scope.mjs set --stage update-tms --type <FE|BE> --task <TASK-ID>`;
   `git-ops locate` + `clean-check` (грязная копия → остановка) + `git-ops branch`
   на autotestBranch. При завершении/остановке — `scope.mjs clear`.
3. `tms-cases.mjs parse --task <папка задачи> --repo <копия автотестов>` —
   поля Zephyr берутся из `.conveyor/tms.json` репозитория автотестов; нет
   файла или он с ошибками → остановка с образцом
   `<CONVEYOR_ROOT>/core/templates/tms.example.json` (сам файл не создаёшь).
   Цель кейса — тексты требований из specification.md по REQ-ID плана
   (неизвестный REQ-ID → `ok:false`; текст без ID — как есть), строки
   разделены `<br>` — передавай `objective` без изменений. Дальше — кейсы с
   готовыми полями:
   `new` создать, `mapped`/`existing` сверить. Полей не сочиняй — бери из
   `testCase`; `null` не передавай.
4. MCP-инструменты Zephyr подбери сам по ролям (создание, чтение, правка,
   поиск, шаги, связь с задачей, текущий пользователь); несколько кандидатов —
   спроси; нет создания при новых кейсах — остановка; curl/REST не годится.
5. Спроси владельца (по умолчанию текущий пользователь Jira) и папку для
   новых кейсов (первыми вариантами — папки существующих кейсов плана).
6. Сверь существующие кейсы: поле автоматизации только ПОВЫШАЙ
   (`raiseOnly`, порядок — `automatedRank`); прочие служебные поля
   (постоянные и по типу задачи из конфига, пустой уровень, связь с задачей) —
   всегда; содержание своих кейсов — по
   плану; чужих и взятых поиском (`adopted`) — только противоречие по
   существу, точечно. Владельца, папку,
   статус, приоритет, метки существующих не трогай.
7. Сводка «создать / обновить / пропустить» и разрешение (всё / только новые /
   выбрать / отмена).
8. Создание по одному: поиск дубля по `testCase.title` (без префикса) →
   создание → СРАЗУ `tms-cases.mjs record --task <папка> --id <заглушка>
   --key <ключ>` (взят найденный — с `--adopted`).
   Затем одобренные правки.
9. `tms-cases.mjs apply --task <папка> --repo <копия автотестов>`;
   validate-artifact отчёта с `--plan` (planMismatch пуст);
   `leftovers.repo` — свои заглушки вне @TmsLink, показать (руками).
   `tms-cases.mjs check-diff` — `ok:false` → без коммита. Коммит ровно
   `repoFiles` (`ref: <TASK-ID> ключи кейсов TMS в @TmsLink`), вопрос про push.
10. `validate-task-folder`; meta.json: `stages['update-tms'] = { done, created,
    updated }` (`done` — когда `tms-cases.mjs pending` пуст: ни в плане, ни
    в коде; чужие заглушки — только в сводку). Сводка. Следующий
    шаг — `/conveyor:run-auto-test`.
