description: Вносит требования в репозиторий системного анализа (ветка <ID>-analysis) и собирает specification.md по диффу этих правок. Второй шаг конвейера, после /conveyor:intent — или сразу, без intent. Аргументы `INTENT-ID | TASK-ID [FE|BE|FE-BE] [номер]`: INTENT-ID заводит новую задачу, TASK-ID продолжает уже заведённую, новый ключ Jira (TASK-ID) с постановкой текстом в чате заводит задачу без intent. Запускается ТОЛЬКО командой /conveyor:create-specification — по одному описанию задачи сам не запускай.

**Корень расширения** — `.gigacode/extensions/conveyor`: conveyor установлен
В рабочий репозиторий, все пути ниже и в файлах этапа — ОТНОСИТЕЛЬНО его
корня (каталога с settings.json). Команды запускай из корня рабочего
репозитория, не уходя `cd` в другие каталоги. `node -e` не используй — inline-код запрещён политикой GigaCode.
Перед первым шагом проверь инструментом платформы (Read/Glob), что есть
`.gigacode/extensions/conveyor/core/stages/_common.md`. Файла нет — останови
этап: GigaCode запущен не из корня рабочего репозитория или расширение туда
не положено; попроси перезапустить GigaCode из корня (INSTALL.md, шаг 4–5).
Не ищи файлы плагина по диску и не угадывай путь.

Этап конвейера conveyor: create-specification. Действуй по общему протоколу
из GIGACODE.md (resolve-config → правила защиты → субагенты), затем выполни
ТОЧНО `.gigacode/extensions/conveyor/core/stages/create-specification.md`.

Агент: system-analyst (core/prompts/system-analyst.md). Этап идёт в две фазы;
после фазы A — цикл ревью (домен systems-analysis) с агентом reviewer, см.
core/stages/_review-loop.md.

Первый аргумент опознавай по файлам:
`docs/specs/tasks/<FE|BE>/<аргумент>/meta.json` — это TASK-ID (продолжение
задачи, тип и номер не спрашиваются),
`intents/<аргумент>/intent.md` — это INTENT-ID (новая задача); ни того, ни
другого, а аргумент — ключ Jira (не `INTENT-…`) — новая задача БЕЗ intent'а:
одним вопросом подтверждение заведения, тип и (если текста после аргументов
нет) постановка, а в вопросе — список заведённых задач с тем же префиксом
проекта, похожие ключи первыми (защита от опечатки); номер не спрашивается,
TASK-ID — ключ Jira. Позиции `[номер]` у такой задачи нет: всё после ключа и
типа — постановка целиком, даже если начинается с числа. Постановка
дословно сохраняется в `meta.json → request` и заменяет intent в обеих фазах,
ветка анализа — `<TASK-ID>-analysis`. Задачу, мигрированную с 1.x
(`intentId: null`), продолжают только по TASK-ID.
