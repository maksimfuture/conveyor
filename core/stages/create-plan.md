# Этап /create-plan — план реализации

**Кто запускает:** разработчик. **Агент и кодовая база** — по типу задачи:
FE → frontend-developer + linkFrontendCodeBase; BE → backend-developer +
linkBackendCodeBase.
**Аргументы:** `TASK-ID`. **Предусловие:** существует `specification.md`.

**Рабочая область:** чтение — ТОЛЬКО кодовая база по типу задачи
(repos.frontend или repos.backend) + specification.md; запись — ТОЛЬКО
артефакты задачи (plan.md, meta.json). Репозиторий анализа, автотестов и
чужая кодовая база не открываются и агенту не сообщаются.

## Алгоритм
1. Определи тип задачи из meta.json → выбери агента и репозиторий кода.
   Установи рабочую область: `scope.mjs set --stage create-plan --type
   <FE|BE> --task <TASK-ID>` (запись в репозитории запрещена).
2. Найди рабочую копию кода (`git-ops locate`) и обнови (`update --mode read`).
3. Запусти агента-разработчика: вход — specification.md + путь к коду. Он
   обязан изучить архитектуру и соглашения проекта и составить `plan.md` по
   `core/templates/plan.md`.
4. Валидация (скилл): каждый шаг привязан к файлам; есть раздел рисков;
   каждый REQ-ID спецификации покрыт хотя бы одним шагом (иначе явно указано,
   почему требование вне плана).
5. Обнови meta.json (`stages.plan.done = true`). Сними рабочую область
   (`scope.mjs clear`).

## Ошибки
- кодовая база недоступна → остановка с инструкцией (4.3);
- валидация покрытия REQ-ID не прошла → один автоматический возврат агенту со
  списком непокрытых REQ-ID; после повторной неудачи — покажи пользователю,
  что осталось непокрытым.
