# Этап /setup — инициализация рабочего репозитория

**Агент:** не требуется (выполняет основная сессия).
**Аргументы:** нет.

## Алгоритм
1. Если `settings.json` уже есть в текущем каталоге — сообщи и предложи
   только дозаполнить недостающее, НЕ затирая существующее.
2. Спроси у пользователя `taskPrefix` (по умолчанию `TASK`).
3. Создай структуру:
   - каталоги `tasks/FE/` и `tasks/BE/`;
   - `settings.json` по образцу `${CONVEYOR_ROOT}/core/templates/settings.example.json`
     (подставь taskPrefix);
   - `.env.example` по образцу `${CONVEYOR_ROOT}/core/templates/env.example`;
   - пустой `.env`, если его нет.
4. Добавь `.env` и `.cache/` в `.gitignore` (создай файл, если его нет).
5. Проверь доступность каждой заполненной ссылки. Для этого сначала
   получи конфигурацию (`resolve-config.mjs`), затем по каждой ссылке:
   `node "${CONVEYOR_ROOT}/core/scripts/git-ops.mjs" locate --link <link> --workspace <root> --repo-cache <bool> --name <key>`
   - локальный путь: существует и является git-репозиторием;
   - git-URL при выключенном repoCache — ошибка конфигурации: подскажи
     указать локальный путь или включить `CONVEYOR_REPO_CACHE=true`;
   - git-URL при включённом repoCache — доступность можно проверить
     `git ls-remote` (через git-ops locate — он клонирует/проверит).

## Ошибки
Непрошедшую проверку ссылки покажи в итоговой таблице с инструкцией
(проверить доступ, URL, ssh-ключи), НЕ прерывая остальную инициализацию.

## Вывод
Таблица по каждой ссылке: OK / ошибка / не заполнено. Напомни, что осталось
заполнить в `.env`, и что следующий шаг — `/create-feature`.

## DoD
Структура создана; проверки ссылок выполнены; пользователю показано, что
настроено и что осталось.
