Заполненный план автотестов по шаблону `core/templates/autotest-plan.md`
(редакция от 14.09.2026, по ревью команды тестирования). Содержимое — задача
MAMGM-198 «Переработка справочника „4.5 Permissions“: колонка
permission_exclude_code», восстановленная по ревью: тот же артефакт, который

Проходит `validate-artifact --type autotest-plan`: `ok: true`, незаполненных
мест каркаса нет.

## Что изменилось против прежнего формата

| Было | Стало |
|---|---|
| «Итого» сверху, «Объект тестирования» ниже | «Объект тестирования» сверху, «Итого» внизу — сводка по фактам разделов выше |
| Разделы «Что переиспользуем» и «Шаги реализации тестов» | Удалены: класс и объём работ — колонки «Класс» и «Реализация» таблицы автотестов |
| Кейс = строка таблицы + описание блоком `### TC-N` под ней | Кейс целиком в строке: колонки «Шаги» и «Ожидаемый результат» |
| ID `TC-N` и `AT-N` | ID теста в Jira (`@TmsLink`): `MAMGM-T239`; у нового теста — `MAMGM-T999-N` со сквозной нумерацией |
| Колонка «Автотест» со значением `AT-N` | Она же, но `да` / `нет`: ID автотеста дублировать не нужно — связь даёт общий ID, а колонка показывает покрытие с одного взгляда и сверяется валидатором с таблицей автотестов |
| Подразделы «Новый функционал» / «Регресс» | Колонка «Вид тестирования»: `НФ` / `Регресс` |
| Чекбоксы шагов `- [ ]` → `- [x]` | Колонка «Статус» таблицы автотестов |
| «Уровни тестирования»: выбранные + отклонённые | Только те уровни, на которых будут написаны тесты |

## Правила оформления ячеек

Их проверяет валидатор, поэтому нарушение видно сразу, а не на ревью:

- в первой ячейке строки — **только ID**, без пояснений рядом; ID не
  повторяется в пределах таблицы;
- «Шаги», «Ожидаемый результат», «REQ-ID», «Автотест», «Класс», «Реализация»
  заполнены у каждой строки; переводов строки в ячейке не бывает — шаги идут
  подряд (`1) … 2) …`);
- «Автотест» — только `да` либо `нет`, и значение сверяется с таблицей
  автотестов: `да` требует строки с тем же ID там, `нет` — её отсутствия и
  упоминания кейса в «Что не автоматизируем»;
- вертикальная черта внутри ячейки экранируется как `\|`, иначе строка
  разъезжается на лишнюю колонку и «Статус» читается из чужой ячейки;
- угловые скобки в тексте ячейки не используются: их читает детектор
  незаполненных мест каркаса и вернёт готовый план на доработку.

# План автотестов: Переработка справочника «4.5 Permissions»: колонка permission_exclude_code (MAMGM-198)

## Объект тестирования
- По спецификации проверяем колонку `permission_exclude_code` в таблице `main.permissions` и проброс поля `permissionExcludeCode` в ответ справочника Permissions через `/dictionary`.
- Критерии приёмки: колонка создана и nullable (REQ-1, REQ-5); 15 пар / 30 записей заполнены симметрично (REQ-3); 27 записей без противоположности имеют NULL (REQ-4); значение — существующий `code` (REQ-3); состав справочника не изменился; контракт `/dictionary` не сломан.

## Уровни тестирования
- **DB** — задача бэкенда добавляет исполняемую колонку в `main.permissions`; на уровне БД напрямую проверяются все ключевые критерии приёмки, и в репозитории есть готовый слой DB-тестирования таблиц.
- **API** — поле прокидывается в ответ `/dictionary`, поэтому сервисный контракт проверяется через существующий `NsiService.getDictionary`.

## Что не автоматизируем и почему
- **REQ-2 (adoc-таблица `[cols="7*"]`)** — канонический файл живёт в репозитории системного анализа, вне скоупа автотест-репозитория. Кейсы: MAMGM-T999-7
- **REQ-5-note (DBML-определение с колонкой и note)** — раздел в репозитории системного анализа, автотестами не читается. Кейсы: MAMGM-T999-8
- **REQ-6 (правило формирования пар в `.adoc`)** — текст правила в документации не является проверкой поведения приложения. Кейсы: MAMGM-T999-9

## Приложение: решения и координация
- **Уровень регресса: DB + один API-смоук** — фактическое изменение в данных, там уже есть сверка состава; API-смоук добавлен, чтобы контракт `/dictionary` после появления нового поля остался консистентен эталону.
- **Значение колонки в БД — `code`, а не `objectId`** — принято в спецификации; автотест валидирует наличие `code` в наборе кодов записи.
